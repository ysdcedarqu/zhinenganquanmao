## 定位模块方案对比

| 方案 | 精度 | 功耗 | 成本 | 适用场景 |
|------|------|------|------|----------|
| GNSS（GPS/北斗） | 5-10m | 中 | 低 | 室外开阔区域 |
| UWB | 10-30cm | 高 | 高 | 室内精确定位 |
| BLE 信标 | 1-5m | 低 | 低 | 室内区域 |

初步倾向 **GNSS + BLE 混合方案**：室外用 GNSS，室内用 BLE 信标辅助定位，兼顾精度和功耗。

### 三、关键维度深度分析

#### 3.1 功耗与续航 ⭐ 决定性因素

| 场景 | Orange Pi Zero 3W | ESP32-S31 |
|:---|:---|:---|
| **空载功耗** | ~3–5W | ~0.3–0.5W |
| **满载功耗** | ~10–15W | ~1–2W |
| **待机功耗** | 无真正待机 | Deep-sleep μA 级 |
| **3000mAh 续航估算** | 满载 < 1h，空载 ~3h | 满载约 10–12h，间歇工作整工班 |

**结论**：OPi 功耗是 S31 的 **5–15 倍**。安全帽是电池供电、密闭空间，功耗直接决定续航、散热、电池重量，这是 S31 的最强优势。

#### 3.2 AI 能力

| 维度 | Orange Pi Zero 3W | ESP32-S31 |
|:---|:---|:---|
| **AI 算力** | 3 TOPS NPU | 向量指令加速 |
| **模型支持** | TF/PyTorch/ONNX 全栈 | ESP-NN / TensorFlow Lite Micro |
| **安全帽 AI 需求** | 跌倒检测（IMU 规则） | ✅ 轻松胜任 |
| | 语音唤醒/命令词 | ✅ ESP-Skainet 生态 |
| | 佩戴检测（传感器逻辑） | ✅ 轻松胜任 |

**结论**：安全帽的 AI 需求全部是轻量级边缘推理，S31 算力刚好够用。OPi 的 3 TOPS NPU 严重过剩，代价是功耗失控。

#### 3.4 开发复杂度

| 维度 | Orange Pi Zero 3W | ESP32-S31 自画板 |
|:---|:---|:---|
| **门槛** | 低，Python 即可 | 中高，C + 硬件设计 |
| **参考设计** | 无专用参考 | ✅ **Korvo-1 直接参考** |
| **稳定性** | Linux 可能 OOM | RTOS 实时可靠 |
| **启动时间** | 几十秒 | 毫秒级 |
| **PCB 设计** | 不需要 | 需要，但 Korvo-1 原理图可复用 |
| **开发周期** | 1–2 周原型 | 4–6 周（含硬件，有参考可缩短） |

#### 3.5 成本分析

| 成本项 | Orange Pi Zero 3W | ESP32-S31 自画板 |
|:---|:---|:---|
| **核心板/模组** | ¥99–199 | ¥25–40（WROOM-3 预估） |
| **PCB 设计** | ¥0 | ¥5,000–10,000（一次性） |
| **综合 BOM（≥1K）** | ¥99–199 + 模组 | ¥40–65（全集成单板） |

**结论**：量产阶段 S31 方案 BOM 仅为 OPi 的 1/3–1/2，且全集成单板省去模组间连接器和线缆，可靠性更高。

### 五、结论：ESP32-S31-WROOM-3 模组 + 自画板

**淘汰 OPi 的核心理由**：功耗 5–15W 对电池供电设备是致命伤，散热在密闭帽体内无法解决。

**选择 ESP32-S31 的核心理由**：

1. **功耗低一个数量级**：0.3–2W，3000mAh 电池撑一个整工班
2. **Wi-Fi 6 + BT 5.4 + Zigbee/Thread**：抗干扰 + 多协议生态
3. **Korvo-1 是现成参考设计**：音频（ES8389 + 双麦 + 3W PA）、摄像头（OV3660）、microSD 三大子系统原理图直接复用
4. **量产成本低**：全集成单板 BOM ¥40–65，约为 OPi 的 1/3
5. **实时性强**：RTOS 毫秒级启动，不会 OOM
